# FPTU Lost & Found Mobile

Expo SDK 58 and TypeScript app for FPTU Lost & Found. Navigation uses Expo Router with one stack nested inside each bottom tab.

## Run

1. Copy `.env.example` to `.env` and set `EXPO_PUBLIC_API_URL` to an API address reachable from the device.
   - Android emulator: `http://10.0.2.2:3001/api`
   - Expo Go on a physical device: `http://<computer-LAN-IP>:3001/api`
2. From the repository root, run `npm install` once, then `npm run dev:mobile`.
3. Open the QR code in Expo Go or press `a` to open an installed Android emulator.

When running in development, `EXPO_PUBLIC_API_URL` defaults to `http://localhost:3001/api` if it is unset. Preview and production builds require `EXPO_PUBLIC_API_URL` and reject localhost addresses so the deployed app cannot silently target a developer's machine.

## Shared foundations

- `src/services/api.ts`: Axios client, SecureStore access token, cookie-backed refresh, API errors, and authenticated `mediaBlob(path)`.
- `src/app/(tabs)`: five primary tabs with a nested stack each. Admin and Staff tabs are role-gated.
- `src/components/ui`: shared controls and network state banners.
- `src/constants/theme.ts`: mobile color, spacing, and radius tokens.

The backend refresh endpoint rotates an HTTP-only `lnfs_refresh` cookie and returns a new access token in JSON. The client enables credentialed requests and stores the access token in SecureStore.

## Android APK preview

The `preview` EAS profile creates an installable APK (`com.fptu.lostfound`). The app's Android version code is set in `app.json`; increment it before producing a later release if the previous APK is already installed.

1. Install Node.js dependencies from the repository root with `npm install`.
2. From `apps/mobile`, authenticate the EAS CLI using an Expo account that can create or access this project:

   ```powershell
   npx eas-cli@latest login
   npx eas-cli@latest project:init
   ```

   `project:init` links this app to the Expo project and writes its project ID into the app configuration. Keep that ID in version control; do not commit Expo access tokens.
3. Add `EXPO_PUBLIC_API_URL` to this Expo project's `preview` environment with the deployed API address (Expo dashboard → Project settings → Environment variables, or `npx eas-cli@latest env:set --name EXPO_PUBLIC_API_URL --value https://<api-host>/api --environment preview --visibility plaintext`). This public URL is embedded in the app; do not use a developer computer's `localhost` for a physical-device APK.
4. Start the cloud build:

   ```powershell
   npx eas-cli@latest build --platform android --profile preview
   ```

5. After EAS Build succeeds, open the build details URL printed by the CLI and download the APK. On a phone, open that URL directly, allow installation from the browser if Android asks, then install and launch the app. An emulator can install the selected build with `npx eas-cli@latest build:run --platform android --latest`.

The build URL is generated by Expo for each successful build and is not a permanent link stored in this repository. The build requires an authenticated Expo account and a working EAS project link.
